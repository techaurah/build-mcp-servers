# Solution for Lesson 13: State, files, and databases inside a server

Contract: inputs are a lead id and a target stage. Legal move (forward in the order NEW, QUALIFIED, BOOKED, with LOST reachable from any stage): update the row in one parameterised statement, commit, return the lead's id, old stage, and new stage. Backwards move: change nothing, return a structured refusal with the current stage and the rule stated, which the tool layer turns into an isError result the model can explain. Unknown lead: same refusal shape with a not found reason, never an exception leaking SQL text. The rule lives in the logic and store layer, not in prompts or tool descriptions, because descriptions advise models while layers enforce for every caller, including buggy and hostile ones. That placement is the LeadPipe stage rules pattern in miniature.
