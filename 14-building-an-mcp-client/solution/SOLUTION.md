# Solution for Lesson 14: Building an MCP client in Python

Design: `request` keeps raising a typed ProtocolError carrying code and message for malformed conversation failures (parse, invalid request, internal), because no caller can fix those by asking differently. Tool level outcomes never raise: isError results return as values, since recovery is the caller's or model's job. The unknown tool or unknown method case (-32601, -32602 from tools/call) raises a distinct UnknownToolError subclass, so a product client can catch exactly that, re list tools, and retry once with a verified name. Centralising the distinction matters because five call sites inventing five retry policies is how clients end up retrying parse errors forever; one contract in the client gives the whole program one behaviour.
