# Solution for Lesson 18: Streamable HTTP: the remote transport

Ship the demo over stdio, launched by the reviewer's own host, or behind the platform's private networking with the endpoint unlisted and the server in read only demo mode with seeded data. Counter to later auth: first, the tool surface gets designed against anonymous callers, so write tools and broad resources that are fine in a demo become liabilities the day the URL leaks, and URLs always leak. Second, clients and saved configs multiply: every integration built against the open endpoint must be re issued tokens and re configured, so the migration you deferred lands on your users instead of your roadmap. Auth shapes the design (whose leads may this caller see?) and designs resist retrofitting; Lesson 19's model is not a wrapper you add, it is a question every tool answer depends on.
