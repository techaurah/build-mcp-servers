# Solution for Lesson 30: Harden and test LeadDesk: approval writes, dry runs, and the gate suite

Setup: capture a lead and move it to QUALIFIED through the legal path. Call: attempt to move it back to NEW. Assertions: one, the stored stage is still QUALIFIED after the call, because a refused move changes nothing; two, the returned value is the structured refusal from Lesson 13's contract, carrying the current stage and the rule, which the tool layer renders as an isError result whose text a model can explain ('stage is QUALIFIED and stages move forward only'). Bucket: caller error, since the request was well formed but impermissible, which is why it is an isError result rather than a protocol error, and why no automatic retry should ever repeat it. If your implementation raised a bare exception instead, the fix belongs in the logic layer's contract, with the test you just described as its proof.
