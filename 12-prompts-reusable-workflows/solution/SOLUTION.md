# Solution for Lesson 12: Prompts: reusable workflows users invoke on purpose

Model answer: arguments, none required; an optional `focus` string exists in stronger designs but the morning workflow succeeds without it, and every required argument is friction at 8am. Message text, in order: read `leaddesk://pipeline/summary` first so numbers come from the server, not memory. Call `list_leads` and identify hot band leads and any lead untouched in stage NEW. Present counts by stage, then hot leads by name with their need in one line each, then exactly one suggested next action, the single highest leverage move, stated plainly. Close by offering the `qualify-lead` prompt for any lead the owner picks. Notice what the text does not do: it does not send anything, promise anything, or invent a lead; every fact routes through a tool or resource with its own guards.
