# Solution for Lesson 16: Debugging: stdout traps, logs, and the failure catalogue

One: whether the host or its config changed anyway (updates rewrite and relocate configs; 'I changed nothing' means 'I intended nothing'). Two: whether the exact config command still starts the server in a terminal, which rules out interpreter, path, and code load failures in one run. Three: whether the environment the host launches with still has what the server needs (a moved virtualenv and an expired credential both present as connection failures). Four: the host's own logs and the Inspector against the same command, applying the Lesson 09 split. Only after those four does server code become a suspect, because a server that ran yesterday and was not edited is rarely the thing that changed; its context is.
