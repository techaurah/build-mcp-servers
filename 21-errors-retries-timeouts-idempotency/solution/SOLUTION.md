# Solution for Lesson 21: Errors, retries, timeouts, and idempotent writes

The course's rule: a slot holds one event per calendar, full stop, because the resource being protected is the business's time, not the lead's intent. Implementation: keep a second index from slot to event id, written in the same commit as the event. On a booking call, resolve in order: if the key exists, return its event (idempotent retry). Else if the slot is taken, return an isError shaped refusal naming the slot and the existing event id, so the model can offer the caller another slot instead of a mystery failure. Else create, recording both indexes atomically. If your business genuinely allows parallel bookings (two chairs, two stylists), the slot key becomes slot plus resource id, and the rule survives with a wider definition of the protected resource; what does not survive scrutiny is having no rule at all.
