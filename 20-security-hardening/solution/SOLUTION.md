# Solution for Lesson 20: Security hardening: tool poisoning, prompt injection, and sandboxing

One: do not update in place; fetch the new version beside the old. Two: diff the tool catalogue, names, schemas, and especially descriptions, reading every changed description as code, because for the model it is. Three: run the new version in the Inspector against test data and compare behaviour on your three most used calls. Four: check what new reach it wants (env vars, file paths, network), and refuse growth you did not expect. Five: swap the config to the new version deliberately, keep the old version runnable for a rollback, and note the version in your own records. The principle: a description change is a behaviour change for a model driven system, and is reviewed like one.
